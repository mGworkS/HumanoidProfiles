# Legende

Diese Begriffe gelten für Übersichten und Steckbriefe. Bedingungen und Quellen am einzelnen Wert haben Vorrang vor einer allgemeinen Beschreibung.

## Quellen und Kenntnisstand

| Kennzeichnung | Bedeutung |
| --- | --- |
| K | Angabe aus dem bereitgestellten Projektkatalog. Bei dieser Übernahme nicht nochmals an jeder Herstellerquelle geprüft. |
| H | Herstellerangabe oder Herstellerdemonstration. Kein unabhängiger Testnachweis. |
| B | Weiterer Beleg oder redaktionell dokumentierte Einordnung. Die genaue Evidenzart steht im Steckbrief. |
| Belegt | Die Aussage ist durch die angegebene Quelle dokumentiert. Aussage und Quellentyp gemeinsam lesen. |
| Eingeschränkt belegt | Quelle, Bedingungen oder Übertragbarkeit begrenzen die Aussage. |
| Angekündigt | Geplante Eigenschaft oder Verfügbarkeit. Umsetzung beziehungsweise Lieferung noch nicht bestätigt. |
| Widersprüchlich | Quellen oder Versionen liefern abweichende Angaben. |
| Unbekannt | Kein ausreichender Nachweis erfasst. Bedeutet weder Nein noch einen Zahlenwert von null. |
| Nicht erfasst | Dieses Merkmal wurde noch nicht in den Datensatz übernommen. |
| Nicht veröffentlicht | Die ausgewertete Quelle gibt den Wert nicht bekannt. |
| Nicht anwendbar | Das Merkmal passt sachlich nicht zu dieser Bauform oder Konfiguration. |
| Aus dem Bestand | Quellenlink oder Einordnung wurde übernommen und noch nicht erneut geprüft. |

Ein Katalogeintrag kann als Datensatz vollständig erfasst sein, obwohl viele technische Angaben noch offen sind. Erfasst und fachlich geprüft sind verschiedene Bearbeitungsstände.

## Technik und Einheiten

| Begriff | Bedeutung und Leseregel |
| --- | --- |
| Ursprungsland | Herkunft der Entwicklung beziehungsweise Entwicklungsorganisation. Kein Nachweis des Fertigungslands. Mehrere Länder sind möglich. |
| Höhe | Standhöhe oder ausdrücklich genannte Arbeitshaltung. Bei verstellbarer Höhe gilt der angegebene Bereich. |
| Eigenmasse / Gewicht | Masse des Roboters. Batterie, Hände und Zubehör können je nach Quelle enthalten oder ausgenommen sein. |
| Payload / Nutzlast | Zulässige oder demonstrierte zusätzliche Last. Lastbezug und Bedingungen sind wesentlich. |
| Je Arm | Last eines einzelnen Arms. Nicht ohne Nachweis zur beidhändigen Nutzlast verdoppeln. |
| Beidhändig | Gesamtlast bei Nutzung beider Arme. Kein Wert je Arm. |
| Traglast beim Gehen | Last, während sich der Roboter fortbewegt. Kann von der Last im Stand abweichen. |
| Nominal / dauerhaft | Für die genannten Betriebsbedingungen vorgesehene Last. Kein allgemeiner Nachweis einer ganzen Arbeitsschicht. |
| Spitze / maximal | Obergrenze unter bestimmten Bedingungen. Keine zugesicherte Dauerlast. |
| Demonstrierte Last | In einem bestimmten Versuch gezeigte Last. Kein allgemeiner Traglastnachweis. |
| Reichweite | Nur mit Bezugspunkt sinnvoll: Armlänge, horizontaler Arbeitsraum und erreichbare Höhe sind verschiedene Angaben. |
| IP Schutzart | Kennzeichnung des Gehäuseschutzes gegen Fremdkörper und Wasser. Gilt nur für den beschriebenen Prüfumfang und die geprüfte Konfiguration. |
| IPX0 | X benennt keinen angegebenen Schutzgrad für die erste Ziffer; 0 bedeutet keinen ausgewiesenen Wasserschutz. Daraus keinen Staubschutz ableiten. |
| DoF / Freiheitsgrade | Unabhängige Bewegungsachsen. Zählungen mit oder ohne Hände, Finger und mobile Basis nicht ungeprüft vergleichen. |
| m / cm / mm | Meter, Zentimeter, Millimeter. 1 m = 100 cm = 1.000 mm. |
| kg | Kilogramm. In den Profilen als Masseneinheit für Roboter und Last verwendet. |
| m/s / km/h | Geschwindigkeit. 1 m/s = 3,6 km/h. Testspitze und Arbeitsgeschwindigkeit unterscheiden. |
| Wh / kWh | Gespeicherte elektrische Energie. Daraus allein keine Laufzeit berechnen. |
| Ah | Elektrische Ladungsmenge. Für einen Energievergleich wird zusätzlich die Spannung benötigt. |
| V | Elektrische Spannung. |
| min / h | Minuten beziehungsweise Stunden. Laufzeit hängt von Tätigkeit und Belastung ab. |
| degC / °C | Grad Celsius, etwa für den zulässigen Betriebstemperaturbereich. |
| TOPS | Angegebene Rechenleistung für bestimmte Operationen. Kein unmittelbarer Maßstab für Autonomie oder Arbeitsleistung. |

## Zugang und Geschäftsmodell

| Begriff | Bedeutung |
| --- | --- |
| Kauf angeboten | Ein Bestellweg wird angeboten. Lagerbestand, Region, Preis und Lieferzeit sind separat zu bestätigen. |
| Kaufanfrage | Anbieter prüft Konfiguration und Angebot individuell. Kein sofort lieferbares Standardpaket zugesichert. |
| Vorbestellung / Reservierung | Zugang für eine künftige Bereitstellung. Keine bestätigte Auslieferung. |
| Projektzugang / Pilot | Zugang im Rahmen eines vereinbarten Projekts oder Tests. Kein allgemeines Verkaufsangebot. |
| Vorgestellt / angekündigt | Öffentlich vorgestellte kommerzielle Entwicklung. Funktionen, Termine und Zugang können noch offen sein. |
| Externer Zugang nicht bestätigt | Es fehlt ein bestätigter Zugangsweg für Dritte. Das beweist nicht, dass eine Kooperation unmöglich ist. |
| RaaS | Robotics as a Service. Nutzung gegen laufendes Entgelt; Hardware, Software, Wartung und Bedienunterstützung können unterschiedlich enthalten sein. |
| Abo | Wiederkehrende Zahlung für bestimmte Leistungen oder Funktionen. Verpflichtende und optionale Abos unterscheiden. |
| Marktangebot und Einsatzreife | Ein kaufbarer Roboter ist nicht automatisch für einen konkreten Arbeitsprozess geeignet. |

## Lebenszyklus und Ansichten

| Begriff | Bedeutung |
| --- | --- |
| Erstvorstellung | Früheste im Datensatz belegte öffentliche Vorstellung oder Ankündigung der erfassten Ausführung. |
| Verkaufsstart | Beginn des belegten Marktangebots. Kein automatischer Nachweis der ersten Auslieferung. |
| Erste bestätigte Auslieferung | Dokumentierte Übergabe an einen externen Empfänger. |
| Produktion eingestellt | Herstellung der betreffenden Ausführung beendet. Verkauf von Restbeständen oder Support können weiterlaufen. |
| Entwicklung beendet | Entwicklung dieser Plattform beendet. Kein automatisches Ende aller Nutzung oder Forschung beim Hersteller. |
| Supportende | Ende der benannten Unterstützungsleistung. Hardware, Software und Ersatzteile können unterschiedliche Termine haben. |
| Aktuelle Auswahl | Geeigneter Ausgangsbestand für das Screening mit aktuellem Zugang oder dokumentierter kommerzieller Vorstellung. Keine pauschale Eignungsfreigabe. |
| Historie | Frühere oder historisch eingeordnete Systeme in eigener Tabelle. Frühere Produktion oder Verkauf werden nicht vorausgesetzt. |
| Forschung ohne bestätigten externen Zugang | Forschungsplattformen mit ungeklärtem Zugangsweg, in eigener Tabelle. Kaufbare Forschungsprodukte können dagegen in der aktuellen Auswahl stehen. |
| Modell / Variante | Bestimmtes Robotersystem beziehungsweise ausdrücklich abweichende Ausführung. |
| Familie | Sammelbezeichnung für mehrere mögliche Ausführungen. Werte gelten nicht automatisch für jedes Mitglied. |
| Entwicklungsprogramm | Projekt ohne hier bestätigte eindeutige Modellbezeichnung. Separat von Modellen gezählt. |

## Software, Integration und Offenheit

| Begriff | Bedeutung |
| --- | --- |
| SDK | Software Development Kit: Werkzeuge und Bibliotheken für die dokumentierten Entwicklungsfunktionen. |
| API | Programmierschnittstelle für bestimmte Befehle oder Daten. Umfang und Zugangsrechte prüfen. |
| ROS / ROS 2 | Softwareframeworks für Robotik. Unterstützung bedeutet keine Freigabe sämtlicher Roboterfunktionen. |
| Policy | Trainiertes Steuerungsmodell, das aus Beobachtungen Aktionen ableitet. Gilt für bestimmte Aufgaben und Schnittstellen. |
| Policy Training | Eigene Steuerungsmodelle trainieren. Physische Ausführung und kommerzielle Nutzung brauchen eigene Nachweise. |
| RL | Reinforcement Learning: Lernen durch Rückmeldungen einer definierten Aufgabe. |
| Simulation / Sim2Real | Virtuelle Erprobung beziehungsweise Übertragung auf den realen Roboter. Eine Simulation belegt noch keinen erfolgreichen realen Einsatz. |
| Teleoperation | Ein Mensch steuert den Roboter aus der Ferne. |
| Autonomie | Selbstständiges Handeln innerhalb bestimmter Aufgaben und Bedingungen. Keine pauschale Eigenschaft für alle Tätigkeiten. |
| Quellcode verfügbar | Programmcode ist zugänglich. Welche Änderungen und Nutzungen erlaubt sind, bestimmt zusätzlich die Lizenz. |
| Gewichte verfügbar | Parameter eines trainierten Modells sind zugänglich. Trainingscode und Trainingsdaten können trotzdem fehlen. |
| Firmware | Gerätesoftware, die grundlegende Hardwarefunktionen steuert. |
| OTA | Softwareaktualisierung über eine Netzwerkverbindung. Eine angekündigte Aktualisierung ist noch keine gelieferte Funktion. |
| Marketplace / App Store | Vertriebsplattform für Anwendungen oder Erweiterungen. Drittanbieterzugang, Freigaben und Kosten sind separat zu prüfen. |
| Integrator | Anbieter, der Hardware, Software und Arbeitsablauf zu einer konkreten Lösung verbindet. |
| F&E | Forschung und Entwicklung. |

## Kategorien und Mehrfachnennung

Branche beschreibt den Wirtschaftsbereich, Aufgabe die Tätigkeit und Umgebung die Einsatzbedingungen. Ein Roboter darf in mehreren Kategorien stehen; jeder Link führt zum selben Profil.

Umgebung mit Besuchern oder Kunden bezeichnet etwa Empfang, Verkaufsraum oder Museum. Dieser Umgebungstag ist kein Sicherheitsnachweis. Bau ist eine Branche; Außenbereich ist eine Umgebung. Eine Baustellendemonstration beweist nicht automatisch Außenbetrieb.

Die [Herstellererläuterung zu IP Schutzarten](../quellen/src_ip_explanation.md) bietet zusätzliche Beispiele. Konkrete Normprüfungen und Geltungsbereiche sind am jeweiligen Roboternachweis zu prüfen.
